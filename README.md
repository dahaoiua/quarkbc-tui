# QuarkBC

夸克网盘的终端小工具（TUI）：把网盘文件变成**比特彗星 `bc://` 链接**并一键唤起下载，
顺带支持**分享链接批量转存**和**手机直接下载**。

```
┌ QuarkBC · 夸克网盘 → 比特彗星 ─────────────────────────────────┐
│ 生成链接(b)  唤起下载(w)  手机下载(m)  上级(u)  刷新(r)  批量转存(t)  扫码登录(l)  设置(s) │
│ √   类型   名称                            大小                │
│     目录   Movies/                         -                   │
│  ✓  文件   movie.mkv                       4.2 GB              │
└───────────────────────────────────────────────────────────────┘
```

## 它到底做了什么

`bc://http/<base64>` 是比特彗星自己的「命名链接」，内容是一个 HTTP 下载任务描述，
**跟 BitTorrent 协议没有任何关系**。本工具做三件事：

1. 用登录态换会话令牌（`acquire_dl_token`），批量取 `download_url` 直链
2. 把「直链 + UA + Cookie」拼进 `AA/…ZZ` 帧，Base64 后输出 `bc://` 链接
3. `os.startfile("bc://…")` 交给系统协议处理器，**比特彗星不用提前打开**就会拉起并开始下载

因此它绕开了客户端限速那一套：链接里带了登录 Cookie，BT 是按你的账号身份去取的。

## 功能

- **扫码登录**：夸克 APP 扫码，自动拿 Cookie 并落盘；`__puus` 轮换会自动吸收续期，不用反复登录
- **目录浏览**：上下键/鼠标点行进入目录，空格勾选（支持多选）
- **两个出口**
  - `b` 生成链接 → 结果页可复制单条/全部
  - `w` **一步到位**：勾选 → 取直链 → 直接唤起比特彗星，不进二级页面
- **手机下载**（`m`）：电脑起一个局域网 HTTP 中继，手机扫二维码/输地址就能下，
  任何浏览器、IDM、ADM、Aria2 都行，支持拖动进度条和断点续传。**手机只连一条连接，
  电脑这边开 200 条并行去拉**——夸克按单连接限速，这是速度的关键（详见下文）
- **分享批量转存**：一行一条分享链接（支持 `?pwd=xxxx`、`提取码：xxxx`、`密码 xxxx`、末尾裸 4 位码），
  可指定目标文件夹（多级路径自动创建）。**碰上网盘的单次转存文件数限制会自动拆分**
- **纯鼠标可用**：所有高频操作都有工具栏按钮

## 键位

| 键 | 作用 |

## 安装

需要 Python 3.10+。

```bash
pip install -r requirements.txt
python quarkbc.py
```

Windows 下也可以双击 `启动QuarkBC.bat`。

## 使用

1. 启动后按 `l`，用夸克 APP 扫终端里的二维码（扫不动就点「打开图片扫」）
2. 光标移到文件上按 `space` 勾选，可以多选
3. 按 `w` 直接唤起比特彗星；按 `b` 则先看链接再决定
4. 转存：按 `t`，粘贴分享链接（一行一条），填目标文件夹，点「开始转存」

Cookie 存在脚本同目录的 `quarkbc.json`（已在 `.gitignore` 里，不会进仓库），
每次响应轮换下来的新 Cookie 会自动写回，所以正常使用不会过期。

## 手机下载（`bc://` 在手机上为什么用不了）

先说结论：**`bc://` 只对 Windows 版比特彗星有意义**，手机上没有、也不会有 App 支持它——
它是比特彗星的私有任务格式，不是标准协议。

剥掉这层壳之后是一条 HTTP 直链，但它要求请求同时带**桌面端的 UA 和你的登录 Cookie**，
夸克 CDN 才给数据。手机浏览器/下载器给不出这两个头，直接打开只会 403（或者下一个几 KB 的错误页）。

所以这里反过来做：**让电脑当代理**。

```
手机 ──HTTP──> 电脑 127.0.0.1:8765 上的中继 ──带 UA+Cookie──> 夸克 CDN
      <───── 原样转发字节 ─────
```

1. 电脑上勾选文件，按 `m`
2. 弹出窗口里出现**二维码 + 局域网地址**（形如 `http://192.168.1.12:8766/xxxx/`）
3. 手机连同一个 Wi-Fi，扫码或手输地址，页面上点条目就开始下载

手机侧不需要装任何东西，浏览器、IDM、1DM、ADM、Aria2 都行。中继支持 `Range`，
所以**拖进度条、断点续传都正常**；中文文件名用 RFC 5987 传给手机，不会存成 `%E4%B8%AD…`。

### 速度：为什么必须多连接

夸克 CDN 对**单条连接**限速，实测单连接只有 1.2~1.4 MB/s，而且并发请求之间
**不共享这个额度**——所以比特彗星把连接数开到 200 就能跑满，原理是一样的。

问题在于手机浏览器只会开一条连接。如果中继也只向上游开一条，手机拿到的就永远只有
那 1 MB/s，看起来「跟直接下没区别」。所以并行是在**电脑这边**做的：

```
手机 ──1 条连接──> 中继 ──200 条 Range 并行──> 夸克 CDN
                （乱序取，按单元号拼成顺序流）
```

实测（同一条 63GB 直链，手机侧单连接从走中继下载）：

| 中继并发 | 手机实际速率 |
| --- | --- |
| 1 | 1.38 MB/s |
| 200 | **6.61 MB/s（4.8 倍）** |

几个实现上的取舍：

- **默认 200 条**，和比特彗星默认值一致。设置里按 `s` 能改（1~512）
- 每个 worker 复用一条长连接（`http.client` keep-alive），否则每 1MiB 单元一次 TLS 握手就是 15% 损耗
- 单元大小随并发自适应：200 并发时用 256KiB 单元，把预取窗口压在 64MB 内存内
- 小文件自动降并发（每 512KB 配额一条），否则 200 条建连本身比下载还慢
- 多个文件同时下时总量封顶 2 倍配置值，避免 200×文件数 把本机端口和上游风控一起打爆
- 页面每秒轮询一次进度，**会实时显示当前速率和实际在用的线程数**——速度没起来时，
  一眼能分清是没并行、还是上游就这个上限

自己测一下（用的是你本机网络，晚高峰和别人测的数不是一回事）：

```bash
python quarkbc.py --speedtest              # 对比 1 并发 vs 200 并发
python quarkbc.py --speedtest --conns 64   # 指定要对比的并发数
```

几点注意：

- 手机和电脑必须在**同一局域网**（手机热点也行：电脑连手机热点即可）
- 首次运行 Windows 会弹防火墙提示，勾「专用网络」允许；拒绝的话手机连不上
- 中继只在你打开那个弹窗期间存在，**按 `esc` 关闭就停**，端口立刻释放
- 端口默认 8765，被占用会自动顺延（8766、8767…），窗口里显示的一定是实际在用的那个
- 直链本身有有效期（几小时），过期后手机上下载会报 403，回电脑按一次 `m` 重新生成即可
- 地址里那段随机串每次都不一样，避免同 Wi-Fi 下别人随手翻到你的文件列表

不想一直开着电脑的话，另一条路是**手机装一个能自定义请求头的下载器**（1DM、ADM、Aria2 的
`--header`），把 `User-Agent` 和 `Cookie` 手动填进去，再用 `b` 复制原始直链。可行但每次都要
粘贴两个长串，实际用起来远不如中继省事。

## 命令行

```bash
python quarkbc.py --selftest              # 编码/解析/中继自测（70 项，不联网）
python test_smoke.py                      # 无头 TUI 冒烟测试（46 项，假客户端）
python quarkbc.py --probe "<分享链接>"     # 转存接口探针：分层次定位失败原因
python quarkbc.py --speedtest             # 并发提速自检（会真的下载约 80MB）
```

`--probe` 的用法：先看读接口通不通（判断 Cookie 死没死），再把几种请求变体各打一次，
输出 ✅/❌。夸克这类接口的鉴权行为会随版本变，出问题时这条命令最快定位。
注意它的副作用是真的会转存 1 个条目。

## 四个踩过的坑（改这块代码前值得先看）

**1. 转存 save 走 `drive-pc` 会被判未登录**

同一份 Cookie，`file/sort`、`sharepage/detail` 在 `drive-pc` 上一切正常，
但 `sharepage/save` 稳定返回 `401 / code=31001 require login [guest]`。

看起来像 Cookie 失效，其实是域名问题：save 要发到 **`drive.quark.cn`**。
所以现在写接口（save / task / mkdir）都做了双域名兜底，能用的域名会被记住，
缓存失效还会自动换另一个重试 —— 只试缓存那一个是不够的。

**2. `41035 单次转存文件个数超出用户等级限制` 是任务阶段才报的**

提交转存会正常返回 `task_id`，几秒后轮询任务才失败。这意味着按「顶层条目」分批**没有用**：
一个顶层文件夹只算 1 个条目，能提交成功，但它内部递归的文件总数超限就整任务失败。

现在改成自适应拆分：整批提交 → 命中 `41035` 就对半拆 → 拆到单个文件夹还超限，
就在目标目录建**同名目录**并下钻，把子项按 100 一批递归转存，目录结构保持不变。

实测（非会员账号）：单文件 ✅、27 文件目录 ✅、100 文件一批 ✅、整包 11 个子目录 ❌；
用上述拆分跑完整分享 **496 项、0 失败**。

其它错误码：`41006` 分享不存在/失效，`14001` 参数错（多见于提取码），`32003` 网盘容量不足。

**3. Windows 的 `SO_REUSEADDR` 会让服务「假装绑定成功」**

8765 被别的程序占着时，中继照样 `bind` 成功、日志显示已启动，但手机连过去拿到的是
**那个程序返回的 404**。原因是在 Windows 上 `SO_REUSEADDR` 允许绑已被占用的端口，
而连接会落到原来那个进程手里——典型的「本机看起来一切正常，换台设备就不对」。

现在绑之前先 `connect` 探一次端口，并把 `allow_reuse_address` 关掉：宁可顺延到 8766，
也不要这种假成功。（顺带一提，这类「本机复现不出来」的问题，单测也抓不到，只能靠
换一个客户端去连——手机就是那个客户端。）

**4. 上游不认 `Range` 时并行会变成「越并越慢」**

分段并行的前提是上游对每个 `Range` 请求回 `206` + 精确的那一段。但 CDN 节点策略并不
统一：有的节点无视 `Range`，照样回 `200` 整个文件。这时候如果还按并发去拉，**每一条
连接都会从第 0 字节开始重下一遍**，200 条就是 200 倍流量、而且一条都到不了结尾。

所以中继对每个条目**先探一次**（`Range: bytes=0-0`，顺手拿到真实总长和 `Content-Type`），
只有确认回 `206` 才启用并行；不认 `Range` 的源退回单流顺序转发，日志里也会写明
「单连接，上游不支持分段」。宁可慢，也不能给出错的内容。

另外：`socketserver` 的 `handle_error` 默认把 traceback 打到 stderr——而 stderr 正是 TUI
的全屏画面，手机一锁屏、一取消下载就花屏。它已改成只吞掉断线类异常、其余记一行日志。

## 已知限制

- 唤起 `bc://` 只在 Windows 上有效（依赖协议注册）
- 手机下载需要电脑保持运行且与手机同一局域网；直链过期后要回电脑重新生成
- 中继的地址是 `http://`，浏览器可能提示「不安全」——它只在你家局域网内、且只在弹窗开着时存在
- **200 并发是「用连接数换速度」，上限由夸克那边定**：本机 22 MB/s 的带宽下实测只跑到
  6.6 MB/s，说明瓶颈在网盘侧的账号/IP 限速，不是中继。要更快只能换账号等级或换时段
- 200 条连接会占一些 CPU 和内存（预取缓冲封顶 64MB），老机器可以在设置里调到 32~64
- 转存速度受网盘风控影响，批间隔 1.2s，超大分享会跑比较久
- 接口都是非官方的，夸克改版后可能需要重新对一遍；`--probe` 就是为此准备的
- 本项目只处理你自己的账号与你有权限访问的分享，没有绕过任何付费限制

## 测试

```bash
python quarkbc.py --selftest   # 70 passed
python test_smoke.py           # 46 passed
```

中继的端到端测试会真的起一个本地 HTTP 上游、发真实请求、逐字节比对，并且**在假上游侧
统计并发峰值**来证明「确实在并行」——只断言「字节数对」是不够的，单流也能对。

冒烟测试用 textual 的 `run_test` + 假客户端驱动完整交互链路，
并且断言「真实配置文件一个字节都没被改动」——这条守卫是被一次事故换来的：
早期测试落盘走了默认路径，把用户真实 Cookie 覆盖成了测试假值。

本仓库不包含原始 userscript（`（改）网盘直链下载助手`）。
